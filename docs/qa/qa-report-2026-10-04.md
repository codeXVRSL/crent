## Bugs found and fixed (all in this commit)

| # | Severity | Problem | Fix |
|---|---|---|---|
| 1 | P1 | **Long text widened the whole page.** A description, message or instruction with a long unbroken run (a pasted URL, a hashtag string) stretched the page to 24,000 px sideways. | Global `overflow-wrap: anywhere` on content containers. Verified with a 3,000-char and a 6,000-char input. |
| 2 | P1 | **Valid pitches were rejected.** Browsers submit textarea line breaks as `\r\n`, so a 5,990-character write-up with 140 line breaks arrived as 6,130 characters and hit the database's 6,000 limit, while the form's own counter said it was fine. Same for every textarea in the app. | Every server action normalises `\r\n` to `\n` before validation. |
| 3 | P1 | **Vague validation error.** Any length-limit failure said "Some fields are too short or too long", so the researcher could not tell which of eight fields to fix. | The message now names the field ("Instructions: too short, too long or in the wrong format…") and the raw constraint is logged. |
| 4 | P1 | **Times shown in the server's time zone with no label.** "Reply by Oct 3, 2:19 PM" on a dispute was UTC; a researcher in Manila would read it 8 hours early. 15 places. | New `<When>` component renders every time with a date in the viewer's own time zone (server renders UTC with a label, browser replaces it). |
| 5 | P2 | **Notification badge never cleared** unless the person pressed "Mark all as read". | Viewing the notifications list marks them read; the list still highlights what was unread. |
| 6 | P2 | **Silent failures in Wallet.** Removing a payout method while a withdrawal to it was pending did nothing, with no message; cancelling a withdrawal gave no confirmation. | Both now return a message or confirm at the top of the page (the row disappears, so the confirmation can't live on it). |
| 7 | P2 | **No page titles on dynamic pages.** Public researcher profiles, briefs, disputes, conversations and creator onboarding all had the bare site name as their tab title and no description (bad for search results and for people with many tabs). | `generateMetadata` on profiles (name + headline) and briefs (title); static titles on the rest; descriptions on pricing, help, directory, for-researchers and home. |
| 8 | P2 | **Brand name hard-coded in 22 places** (layout, emails, legal pages, payment descriptions, OG image). A rename (see the launch plan, section 6) would have been error-prone. | `lib/brand.ts` holds `BRAND`; every use reads it. |
| 9 | P2 | **robots.txt** still allowed crawling of `/ideas`, `/favorites`, `/swipe`, `/disputes`, `/notifications`. | Added to the disallow list. |
| 10 | P2 | **Open-redirect edge in `?next=`.** `/login?next=/\evil.com` passed the "must start with /" check; browsers treat `/\` like `//`. | Rejects `/\` as well as `//`. Verified. |
| 11 | P2 | **Over-promising copy.** Three places promised pitches "usually within a day" / "within 24 hours", which an empty marketplace can't keep and which invites bad reviews. | Replaced with what actually happens: researchers in the niche are notified the moment the brief goes live. |
| 12 | P2 | Help FAQ didn't cover the idea board, saved researchers, swipe file, levels, who sees ID photos, taxes, or how to delete an account. | Seven questions added. |
| 13 | P2 | Proof-screenshot link had no accessible name; "Remove payout method" buttons were indistinguishable to screen readers. | `aria-label`s added. |

## Reviewed and found sound

- **Authorisation:** every write goes through a database function that checks the caller, or through row-level security; cross-role pages redirect; another creator cannot open your brief or dispute (404); the CSV export and cron need a session or the secret; the test-payment page only acts on the caller's own payment.
- **Money:** unlocks, refunds, payouts and dispute reversals are atomic with row locks; a triple-click on Confirm unlock charges once; the ledger balances to zero per brief; `hold_hours = 0` behaves (immediate availability, no dispute window).
- **Errors:** email failures are logged and never abort an action; provider errors surface as messages; the webhook returns 500 so the provider retries.
- **Security headers, no `dangerouslySetInnerHTML` except the theme script, no service-role key in client code, signed URLs expire in 5–10 minutes, uploads are type- and size-limited by the storage bucket.**
- **Navigation:** every nav item resolves, exactly one item is active per page, the mobile drawer has all desktop items and closes after navigating, the logo returns to the dashboard inside the app and to the home page outside it.
- **Phone:** no page overflows at 390 px in light or dark mode.

## Seen once, not reproduced

A React hydration warning (#418, text mismatch) appeared once on the researcher's brief page during the first crawl, before the stale server was replaced. It did not reproduce in dev mode (which would have shown the exact text) or on repeated visits. If it shows again, the likely culprits are a time string rendered before `<When>` existed; report the exact page and we'll chase it.

## Product gaps found by this review, now closed (follow-up, same day)

| # | Gap | What was built | Verified by |
|---|-----|----------------|-------------|
| A | No rate limiting on login/sign-up/reset. | Attempts are counted in the database (works on serverless hosting, no Redis): 10 password tries per account per 15 minutes, plus loose per-address limits because many Philippine mobile users share one carrier address. Old rows are pruned by the daily job. | SQL tests (window reset, independent keys, service-role only); browser test: 11th login refused even with the right password |
| B | No self-service account deletion. | Settings → Close account. The database refuses while earnings, a withdrawal, a live brief or an open dispute is attached, otherwise withdraws waiting pitches, deletes ID submissions, payout numbers, saved items and notifications, anonymises the profile, and the auth login is banned and its email freed. Money history stays with the platform. | SQL tests (each blocker, scrubbing, ledger untouched, audit row); browser test: refusal message, confirmation word, logout, login refused |
| C | No admin two-factor login. | Admins must enrol an authenticator app on first login and enter a code on every login after that (Supabase TOTP, AAL2 checked on every admin page and action). Wrong codes are rate-limited; researchers and creators never see it. | Browser test: forced setup, wrong code refused, right code opens the panel, admin pages blocked before the code |
| D | Transactional emails were plain text. | Every email now has a branded HTML version (heading, paragraphs, one button for the link) with the old text as fallback. | Build; manual read of the template |

## Follow-up round, 8 October 2026: security review and accessibility

A second reviewer read the money, authorisation and webhook code line by line. Every finding below was reproduced against the code before fixing, and each fix has a database or browser test.

| # | Severity | Finding | Fix |
|---|---|---|---|
| S1 | Critical | Admin two-factor was only checked by the app's pages. An admin password alone gave an API token that could approve ID checks, change fees, approve payouts and read ID documents directly. | The database's admin check now requires a two-factor session too (`admin_mfa_required`, on by default). Tested both ways. |
| S2 | High | A payment webhook that failed half-way was marked "duplicate" on the provider's retry, so a paid brief could stay unpaid for good. | Retries of unprocessed events run again; the money functions are safe to repeat. |
| S3 | Medium | The email-link callback accepted `/\evil.com` as a "same-site" return address. | Same check as the login page. |
| S4 | Medium | Creators could read a hash of a locked pitch's source video and match candidate videos against it without paying. | The column is no longer readable by users. |
| S5 | Medium | A dispute decided for the researcher after the hold ended skipped a ledger entry, so balances drifted. | The release entry is written in the same step. Tested. |
| S6 | Medium | A hosted site with no payment mode set fell back to test mode with a public webhook token. | On Vercel the mode and a private test token must be set explicitly. |
| S7 | Medium | A payout that errored before reaching the provider stayed "processing" forever; re-approving a failed payout replayed the first attempt. | Errors mark it failed; each approval is a new attempt at the provider. |
| S8 | Medium | "Retry refund" could resend a refund that had already succeeded. | Only failed or manual refunds can be retried. |
| S9 | Medium | Becoming admin didn't require a confirmed email. | Now it does. |
| S10 | Low | Suspended accounts could still open disputes, review, message and receive unlocks. | Blocked in the database for every path. Tested. |
| S11 | Low | Two-factor code limit was per address only. | Added a per-account limit; README tells the operator to tighten Supabase's own auth limits. |
| S12 | Low | Choosing a new payout method left every method marked "default". | Fixed with a dedicated database function; existing data repaired. |

Also in this round:

- **Accessibility.** A new automated audit (axe-core, WCAG 2.1 AA) of 40 pages for all four roles in light and dark mode found 43 colour-contrast failures (status pills, labels, table headers, the dark-mode test-mode badge). Five colour tokens were adjusted; the audit now reports **0 violations**.
- **Error and 404 pages.** There were none, so a crash showed the bare framework error and a wrong link showed the default 404. Both are now branded, explain what happened, and give a reference code for support.
- **Dates.** Calendar dates (planned posting date, source video date) were shown a day early for viewers west of UTC and could trigger the hydration warning seen once on the idea board. They now display the same for everyone.
- **Lesson recorded.** A site-wide loading skeleton was tried and removed: it turned page redirects into client-side redirects and broke ten browser-test steps.

## Follow-up round 2, 8 October 2026: deploy, speed and phones

- **Deploy script dry run.** `npm run test:deploy` runs the one-command deploy against simulated Supabase and Vercel APIs and checks 16 things: Singapore region, the full database setup, every environment variable (secrets encrypted), two-factor switched on, secrets file private and never rotated on re-runs, and a clear stop when a token is missing. All pass. A `.vercelignore` now keeps local `.env` files and documents out of the upload.
- **Speed.** The site now runs in Vercel's Singapore region, next to the database. Before, Vercel's default US region would have added a Pacific round trip to every database call (several per page). The ID-upload and pitch pages load the upload library only when a file is sent, cutting their JavaScript from about 184 KB to 115 KB.
- **Phones.** The floating Feedback button covered card text; it is now a small icon on phones, and pages leave room for it. The wallet's payout form now asks for a bank only when "Bank account" is chosen, from a list of Philippine banks instead of a code to type. The empty earnings table no longer cuts its message off. The dashboard no longer offers "Withdraw" at $0.00.

All suites pass: database, exploratory 38/38, Playwright 2/2, accessibility 0 violations, unit, typecheck, lint, deploy dry run.
